## P0318 implementation

A separate `Quest/NPCGossipChoice.lua` controller handles **direct user clicks only**. It checks that `C_GossipInfo.SelectOption` exists and is ordinary, that the addon owns a current ordinary interaction, that combat lockdown is definitely false, and that the selected source option is an ordinary positive integer ID with available `gossipStatus=0`. Immediately before dispatch it calls the already guarded `NPCGossipSource.Sample()` again and compares NPC title, stage kind, quest counts, row count and all copied choice labels, IDs and statuses. Any mismatch, ambiguity or API/protection restriction **fails open to usable Blizzard stock** (explicit fail-open behavior), without a native call. An accepted click calls `C_GossipInfo.SelectOption(gossipOptionID)` inside `pcall` and dismisses only the addon presentation. No automatic selection, quest acceptance/completion, item/currency transaction, gossip suppression, protected frame write, timer, polling, event reassertion or camera change.

The existing option source remains `enabled=false` for every real option, preserving data-model inertness. The existing shared `NPCOptionList` receives a narrowly separate `SetLiveSelectable` gate so only P0318-controlled live options can receive user input. P previews remain independently gated and unchanged. P0317's historical contract is updated to reflect actual `nativeActions` reporting from the separate choice controller, rather than falsely reporting zero. The H — Gossip Live Status read-only audit reports attempts/successes via its existing nativeActions field. Blizzard gossip and quests remain visible and clickable; native one-window parking is **not** authorized until a complete and safe owned interaction/restoration contract is validated.
