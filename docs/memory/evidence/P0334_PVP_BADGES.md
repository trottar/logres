The user reported missing PvP symbols on the player and current target (L-023). Logres HUD has a player resource bar and sparse target name/percentage but no PvP badge. ## Implementation boundary

`HUD/HUD.lua` adds a compact 32x16 noninteractive PvP label/bronze accent to the existing player resource row and target identity, with the same badge factory for both synthetic preview and live display. Player badge is anchored beyond the resource bar, target badge beyond the sparse target name. Both remain children of the gameplay-only BACKGROUND HUD, so P0331 native menu layering and P0330 health tunnel are intact.

`readOrdinaryPvPFlag(unit)` calls `UnitIsPVP` through `pcall`; it requires `issecretvalue` and tests secrecy before inspecting boolean type or value. Ordinary `true` shows a Logres badge; ordinary `false` hides it; unknown/error/secret hides only the additive badge and retains existing Blizzard fallback. No faction, PvP timer, PvP combat classification, native badge, protected/secret presentation value, HP or aura payload is queried. PvP remains a STATUS visual modifier, not Immersion OFF. No UI ownership, secure action, saved preference, camera or native frame mutation.

Events `PLAYER_FLAGS_CHANGED`, `PLAYER_TARGET_CHANGED`, `PLAYER_ENTERING_WORLD`, and unit-filtered `UNIT_FACTION`/`UNIT_FLAGS` refresh both badge sources without trusting event payloads or polling. `HUD:SetPvPPreview(on)` and `/logres pvppreview [on|off]` + matching developer panel P-tab actions use the production badges but never query live flags while preview is enabled. The native route is present in source but **cannot be considered accepted** before preview appearance and live-state behavior are tested in the client, per D-046.
