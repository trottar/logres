## Publicly documented data capability
`LibQuestieDB` exports entity APIs (`QuestDB`, `NpcDB`, `ObjectDB`, `ItemDB`). `QuestDB.startedBy(questID)` returns quest-start references grouped by entity type, and `NpcDB.spawns(npcID)` provides zone-keyed spawn points such as `{ [12] = { {36.43, 55.89}, ... } }`. `QuestDB.GetAllIds()` permits enumeration; returned ID lists are shared/read-only. `LibQuestieDB.RequireContract(1)` advertises a version-range check for the public entity reads; `LibQuestieDB.contractVersion` and `.minSupportedContract` declare the range. Data returns are copies except ID lists. Scalar zero is a real sentinel, not Lua false. The published API gives candidate known *spawns*, not a live quest-availability enumerator or individual tracking blip results.

## Blockers that must be solved before live icons
1. **Availability != recorded quest start.** Accepted/completed filtering alone is insufficient: required level, race/class/faction, prerequisite chains, phases, repeatable status, server changes and timing may affect whether an exclamation point exists. Never label all unaccepted QuestieDB quests “available”. A provider may expose candidate locations diagnostically; production quest-POI eligibility needs explicit, conservative evidence. Historical QuestieDB spawn coordinates are not current creature visibility.
2. **Map identity and coordinates.** Database spawn keys are old AreaIDs; Logres player/current map uses Blizzard UiMapIDs. Percent coordinates in QuestieDB are 0–100 while Logres compass operates on 0–1 normalized coordinates plus proven yards via current map width/height. Matching names alone is not an authoritative zone mapping. `LibQuestieDB.EraToForever` converts only four documented legacy zones and must not be applied to coordinates already converted in the Forever dataset. The public `Support.Get("ZoneDB")` exists, but its `private.areaIdToUiMapId` source string is NOT a stable public mapping contract. Establish explicit stable, approved mapping without accessing private tables or executing loadstring.
3. **Source/client version.** QuestieDB Forever has flavor-specific source selection and generated TOC modes; its docs explicitly defer some client/older-version acceptance. The authored Forever coordinate/map reference builds are not the user's current `1.60.1.70425` client. Require exact loaded-provider flavor/build/contract checks in client and negative controls before trusting positions. Do not assume installation or force a hard dependency without explicit product approval. Public QuestieDB docs describe `## Dependencies: QuestieDB` for consumers; an optional Logres bridge needs a separate, verified fail-open load order.
4. **Budget/invalidations.** A `QuestDB.GetAllIds()` global sweep on every compass update, event, map change, or frame is unacceptable. A bounded one-time map-scoped index/cache or batch construction is needed, with observable time/candidate limits, invalidation on map/quest-state changes, and no endless timer/polling. Secret-capable values must be rejected before any arithmetic, branching, formatting or indexing.
5. **Semantic separation.** NPC services/known places may become POIs only with a supported category+spawn proof; generic herb/ore “Find ...” tracking selections still do not yield individual detected-object locations. A static database of historical spawns is not identical to the engine's current tracking detections and must not quietly replace their semantics.

## Result and decision boundary
`QuestieDB` is a plausible **optional external data provider candidate**, not an accepted Logres runtime dependency, not part of the P0224 patch, and not proof of available quest/POI coverage. No third-party files or assets are vendored. Keep the stock minimap available, and maintain P0223 focused quest/manual waypoint accepted presentation unchanged. Do not add placeholder glyphs or scrape Blizzard protected pins.

## Exact next engineering experiment
First evaluate **one supported/current Forever map** and a **single explicitly known quest-start NPC/object** through the documented public API, with QuestieDB already installed and enabled in a disposable or normal validated setup (the user decides separately). Check `RequireContract(1)`, loaded flavor, stable AreaID→UiMapID mapping and a known positive/negative spawn coordinate against the native visible quest giver; count differences from current quest acceptance/completion. Only after that bounded positive proof is an optional provider-to-Compass bridge warranted. Service POI and tracking result are independent gates; no fabricated source means no icon. Do not require user travel merely to produce an environmental condition.
