## Cross-component risk order and treatment

**Priority 1: native harmful aura family.** The current `NativeDebuffs.lua` constant line is `local WIDTH, ICON, GAP, MAX = 98, 18, 2, 5`; its native `CustomAuraContainerTemplate` creates restricted aura buttons with no payload inspection. The higher-priority `StatusAuras.lua` uses `ICON_SIZE = 25`, `GAP = 3`, and the restored `PlayerHelpfulAuras.lua` uses the approved 36px/7px Theme family. A shared visual silhouette does **not** require all icons to have identical dimensions. Target harmful v4 box is only 6% x 9%; test a compact multirow 5-effect fit in the client, rather than blindly making a five-wide 25px row. Source/native layout support and secure tooltip/hover need verification. Keep the stock TARGET access and fail open on any unsupported path.

**Priority 2: whole-screen typography/readability.** Match target name, pet/group percentage rows, player resource text, quest objective/progress and compass labels to existing Theme tokens and their approved typographic roles. Treat world backgrounds and UI scale as contrast constraints. No new exact health/classification information.

**Priority 3: action / native-access visual hierarchy.** Existing action 42px bronze family is already strong; preserve dense interaction usability, visual importance of Main over Secondary/Utility/Bar4/5/pet controls, and minimal feedback without duplicate chrome. PET/BUFFS/TARGET and STOCK/MAP/etc native dock should look intentionally integrated but **remain visible and usable** as deliberate fallback. Do not relocate controls outside the 13 approved rectangles without a new layout decision.

**Lower priority / preserve proven art:** quest narrative, Active Quest, context pulses, cast glyph family, resource primitive and continuous health tunnel. Their completed appearance should not be redesigned merely to make a universal style rewrite.
